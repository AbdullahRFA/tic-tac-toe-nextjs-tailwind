## 📁 Project Structure Explained

### 1. **`.next/`**
> Auto-generated by Next.js during build.

- `cache/`, `server/`, `static/`: Internal build assets and optimizations
- `app-build-manifest.json`, `build-manifest.json`: Track compiled files
- `routes-manifest.json`: Maps routes to pages
- `react-loadable-manifest.json`: Optimizes dynamic imports
- `trace/`: Debugging traces
- ✅ You don’t edit this folder — it’s used by Vercel and Next.js

---

### 2. **`app/`**
> Core of your App Router structure.

- `layout.tsx`: Global layout (HTML wrapper, fonts, body styles)
- `page.tsx`: Main page that renders your game
- `globals.css`: Global Tailwind styles (`@tailwind base`, etc.)
- `favicon.ico`: Browser tab icon

---

### 3. **`components/`**
> Reusable UI logic.

- `Game.tsx`: Your main game component — handles board, turns, win/draw detection, and UI

---

### 4. **`public/`**
> Static assets served directly.

- You can place images, fonts, or icons here
- Accessible via `/filename` in the browser

---

### 5. **`node_modules/`**
> Installed dependencies from `package.json`

- Managed by npm
- You never manually edit this

---

### 6. **Config & Metadata Files**

| File | Purpose |
|------|---------|
| `.gitignore` | Tells Git which files to ignore (e.g. `.next/`, `node_modules/`) |
| `eslint.config.mjs` | ESLint rules for code quality |

| `README.md` | Project overview, setup, and documentation |

### 🧠 3. **Game Logic Explanation**

- The board is a 1D array of 9 cells (`Cell[]`)
- Each cell holds `'X'`, `'O'`, or `null`
- I use `useState` to track board state and current player
- `getWinner()` checks all 8 winning combinations
- `useMemo()` optimizes win/draw detection
- On each click:
  - If cell is empty and game is active → place mark
  - Switch turn
- If win or draw → show status and disable board
- Reset button clears the board and sets turn to `'X'`

---

### 🎨 4. **UI/UX Design Choices**

- Responsive layout using Tailwind’s grid and spacing
- Color-coded marks: `'X'` is blue, `'O'` is rose
- Winning cells pulse with yellow highlight
- Hover and active animations for feedback
- Clean card layout with shadow and rounded corners
- Accessible labels (`aria-label`) for screen readers

### 🗣️ 6. **Common Viva Questions & Answers**

**Q: Why use a 1D array instead of 2D?**  
> “It simplifies indexing and matches the flat layout of the grid. Each cell is uniquely indexed from 0 to 8.”

**Q: How do you detect a win?**  
> “I check each winning line — if all three cells match and are not null, that player wins.”

**Q: What happens on a draw?**  
> “If all cells are filled and no winner is found, I show ‘Draw’ and disable further moves.”

**Q: Why use `useMemo` for result?**  
> “To avoid recalculating win/draw logic on every render — it only runs when the board changes.”

**Q: How is the UI responsive?**  
> “Tailwind’s utility classes like `max-w-sm`, `grid-cols-3`, and `p-4` adapt layout across screen sizes.”

**Q: What would you add next?**  
> “AI opponent using Minimax, online multiplayer with WebSocket, and theme toggle for dark mode.”
